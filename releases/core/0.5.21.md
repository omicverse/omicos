## 中文

- SSH：探测暂时失败时，重连会继续使用原来的 Core 和对话，不再误换连接；连接前先核验所选的运行实例，复用已选实例时不再要求远端装有命令行工具；目录探测不受登录 shell 输出干扰；默认端口拒绝连接时会自动改用备用方式；读取身份失败可以重试；远程对话历史直接走已验证的转发端口。
- 中继：拒绝在释放前被接纳的请求；启动失败时保留诊断信息。
- 内核：停止一轮时只取消这一轮自己的执行，共享内核上的其他执行不受影响。
- 命令行：输入历史和草稿按对话分开保存。
- 文件：能区分「目录不存在」和「读取失败」。

## English

- SSH: when a probe fails for a moment, reconnecting keeps the same Core and conversation instead of swapping the connection; the chosen runtime is verified before attaching, and reusing it no longer needs the command-line tool on the remote PATH; directory probes ignore login-shell output; a refused default port falls back automatically again; identity read failures can be retried; remote conversation history goes straight through the verified forwarded port.
- Relay: requests admitted before release are refused, and startup failures keep their diagnostics.
- Kernel: stopping a turn cancels only that turn's own execution; other executions on a shared kernel are left alone.
- Command line: input history and drafts are kept per conversation.
- Files: "directory does not exist" and "could not be read" are told apart.
